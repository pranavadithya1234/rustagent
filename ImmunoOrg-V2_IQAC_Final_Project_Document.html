Abstract

ImmunoOrg-V2 is a next-generation, proactive Endpoint Detection and Response (EDR) ecosystem designed to provide comprehensive system-wide security monitoring and automated threat mitigation. Addressing the limitations of traditional, reactive antivirus solutions, ImmunoOrg-V2 utilizes a distributed architecture featuring a high-performance Rust-based security agent and a centralized Node.js command center. The system implements real-time File Integrity Monitoring (FIM), suspicious process detection, and stateful cross-telemetry correlation to identify sophisticated threats such as ransomware, unauthorized system modifications, and lateral movement attempts. The platform provides administrators with a premium, command-center style dashboard for real-time fleet management, interactive remote remediation (including process termination), and historical threat hunting. Built with a modern tech stack including Rust, Node.js, Redis, and React, ImmunoOrg-V2 ensures high performance, scalability, and stealthy operation, making it a robust solution for modern organizational security.

1. Introduction

As cyber threats evolve in complexity and speed, organizational security requires more than just passive perimeter defenses. Endpoint Detection and Response (EDR) has become a critical component of modern cybersecurity, providing visibility into the activities occurring on individual devices across a network. Traditional solutions often suffer from high resource consumption, lack of real-time response capabilities, and complex deployment workflows. ImmunoOrg-V2 is designed as a streamlined, high-performance EDR ecosystem that combines the efficiency of Rust for low-level system monitoring with the flexibility of Node.js and React for centralized management and visualization. The project focuses on providing real-time observability and proactive mitigation to minimize the impact of security incidents.

2. Problem Statement

Modern organizations face several security challenges:

  • Signature-Based Limitations: Traditional antivirus often fails to detect zero-day exploits and polymorphic malware.
  • Lack of Visibility: Administrators often lack real-time insights into file-level changes and process activities across diverse endpoints.
  • Delayed Response: Manual intervention is often too slow to prevent the spread of fast-acting threats like ransomware.
  • Agent Overhead: Security agents that consume excessive system resources can hinder user productivity and may be intentionally disabled.
  • Information Silos: Fragmented security tools make it difficult to correlate events and perform comprehensive threat hunting.
ImmunoOrg-V2 addresses these by providing a unified, low-overhead, and real-time monitoring and response platform.

5. Scope

ImmunoOrg-V2 covers the entire lifecycle of endpoint security from agent deployment and registration to real-time monitoring, threat detection, automated mitigation, and post-incident investigation. It includes a cross-platform Rust agent (macOS, Windows, Linux), a scalable Node.js backend with Redis queueing, and a React-based frontend dashboard. The system focuses on file system integrity, process management, and network-wide fleet visibility. Future versions aim to include kernel-level monitoring, behavioral AI-based detection, and integration with external SIEM/SOAR platforms.

6. Complete Feature List

6.1 Agent Identity and Fleet Management

  • Deterministic Agent Identity: Automatically registers endpoints using hostname and hardware identifiers to prevent duplicate entries.
  • Real-Time Fleet Status: Monitors the heartbeat and connection state of all deployed agents across the network.
  • Stealth Execution: The Rust agent is designed to run silently as a background daemon, minimizing user interference.
  • Dynamic Registration: New agents automatically register with the command center upon first launch, facilitating rapid deployment.

6.2 System-Wide File Integrity Monitoring (FIM)

  • Real-Time Observation: Continuously monitors critical OS directories (Downloads, Desktop, Documents, System folders) for file changes.
  • Event Tracking: Logs file creation, modification, deletion, and permission changes with precise timestamps.
  • Noise Filtering: Implements intelligent filters to exclude irrelevant system logs and cache files, focusing on actionable security events.
  • Path-Aware Severity: Assigns higher risk scores to changes in sensitive system directories.

6.3 Suspicious Process Detection and Control

  • Live PID Surfacing: Real-time listing of active processes on monitored endpoints.
  • Remote Process Kill: Administrators can remotely terminate any process on an endpoint directly from the dashboard to stop active threats.
  • Banned Process Flagging: Automatically alerts when restricted or known-malicious applications are detected.
  • Process-File Correlation: Links file system changes to the specific processes responsible for the action.

6.4 Intelligent Security Detection and SOAR

  • Suspicious Extension Flagging: Automatically detects and alerts on malicious file extensions (e.g., `.encrypted`, `.sh`, `.exe` in sensitive paths).
  • Ransomware Detection: Identifies rapid, high-volume file modification patterns characteristic of ransomware attacks.
  • Automated Mitigation: Triggers "isolate" commands for critical threats to disconnect compromised devices from the network.
  • Stateful Correlation: Correlates multiple telemetry events (e.g., file change + high CPU + suspicious process) to identify complex attacks.

6.5 Command Center Dashboard and Analytics

  • "Cyber Command Center" UI: A high-end, reactive dashboard with glassmorphism aesthetics and dynamic animations for enhanced engagement.
  • Real-Time Alerts: Surfaces critical security events instantly via Socket.io for immediate analyst attention.
  • Historical Threat Hunting: Searchable interface for querying the persistent telemetry database for past events.
  • Interactive Network Graph: Visualizes the relationship between the technical network nodes and the organizational structure.

6.6 Testing and Simulation

  • Ransomware Simulator: Built-in tool to safely simulate ransomware behavior to test and validate the system's detection capabilities.
  • Agent Health Monitoring: Detailed logging of agent startup, communication, and error states for troubleshooting.

8. Architecture

ImmunoOrg-V2 follows a distributed client-server architecture designed for high throughput and reliability. The Rust Agent operates on each endpoint, collecting telemetry and executing remediation commands. Telemetry is sent to the Node.js Backend via a REST API, where it is placed into a Redis Queue. A dedicated Telemetry Worker processes the queue, performing threat detection and persisting data to SQLite. Alerts are broadcast to the React Frontend in real-time using Socket.io, allowing analysts to interact with the system instantly.

10. Core Workflows

10.1 Agent Deployment and Registration

  1. Agent binary is deployed to the endpoint and executed (often via `start.sh`).
  2. Agent gathers system metadata (hostname, OS) and sends a registration request to the backend.
  3. Backend checks for existing identity; if new, it creates a record in the `agents` table.
  4. Agent begins monitoring the file system and process list based on its configuration.
  5. Dashboard updates in real-time to show the new agent as "Online".

10.2 Real-Time Monitoring and Alerting

  1. Rust agent detects a file modification in a critical directory (e.g., `Documents`).
  2. Agent sends telemetry data to the backend API.
  3. Backend adds the event to the Redis queue.
  4. Telemetry worker analyzes the event; if it matches a threat pattern (e.g., `.encrypted` extension), it generates an alert.
  5. Alert is stored in the database and sent to the React dashboard via Socket.io.
  6. Security analyst sees the flashing alert and the affected node on the dashboard.

10.3 Remote Remediation

  1. Analyst selects an alert or an endpoint on the dashboard.
  2. Analyst views the active process list for that endpoint.
  3. Analyst identifies a malicious PID and clicks "Terminate".
  4. Dashboard sends a command request to the backend.
  5. Backend forwards the command to the specific Rust agent (via long-polling or dedicated socket).
  6. Rust agent executes the process kill and confirms success to the backend.

10.4 Threat Hunting and Investigation

  1. Security analyst opens the "Threat Hunting" tab on the command center.
  2. System queries the SQLite database for historical alerts and telemetry logs.
  3. Analyst filters events by agent, severity, or timeframe to identify attack patterns.
  4. Analyst inspects the SHA-256 hashes of modified files to compare against known malware databases.
  5. Analyst reviews the agent's connection history to identify periods of suspicious offline activity.

13.1 Rust Security Agent

The agent is built with Rust for memory safety and zero-cost abstractions. It utilizes the notify crate for kernel-level file system events and sysinfo for process telemetry. A local JSONL-based queue ensures data persistence during network outages. The agent calculates SHA-256 hashes for modified files to facilitate forensic analysis.

13.2 Intelligent Detection Engine

The detection logic in Phase 2 moves beyond simple pattern matching. It implements a Stateful Correlation Window: if a suspicious process (e.g., nc, curl, or python) is started followed by a file modification in a system-critical directory (like /etc or /usr/bin) within 60 seconds, the system triggers a CRITICAL Correlated Attack alert. Path-aware severity ensures that user-level changes (Downloads) are handled differently than system-level tampering.

13.3 Automated Mitigation (SOAR)

The Mitigation Service acts as an automated security orchestration layer. When a critical threat is flagged by the engine, the system immediately dispatches an isolate command to the agent's command queue. This "Auto-Isolate" feature reduces the Mean Time to Respond (MTTR) from minutes to milliseconds, effectively neutralizing fast-acting threats like ransomware before they can spread.

13.4 Real-Time Command Center

The frontend uses React with Socket.io to maintain a live connection to the backend. The dashboard utilizes custom glassmorphism CSS, providing a high-fidelity "Cyber Command" experience. It supports recursive process group termination, allowing analysts to kill not just a single PID, but an entire application bundle (e.g., Chrome and its helper processes).

15. Expected Outcomes

  • Drastic reduction in detection-to-response time through real-time alerting and remote remediation.
  • Improved security visibility across the entire fleet of organization endpoints.
  • Automated prevention of ransomware spread through intelligent monitoring and SOAR.

16. Limitations

  • Initial version focus on macOS/Linux; Windows support requires further testing of specific system APIs.
  • Detection is currently pattern-based; behavioral AI models are planned for future releases.
  • Network isolation depends on OS-level firewall controls which may be bypassed by advanced malware.
  • Relies on persistent network connectivity between agent and backend.

17. Future Scope

  • Behavioral AI Models: Integrating Machine Learning models for anomaly-based detection of zero-day threats.
  • Kernel-Level Monitoring: Implementing eBPF or macOS Endpoint Security extensions for deeper system call visibility.
  • SIEM Integration: Exporting telemetry to external platforms like Splunk or ELK stack.
  • Mobile Endpoint Support: Extending monitoring to organizational mobile devices.
  • Role-Based Access Control (RBAC): Granular permissions for analysts, administrators, and CISO roles.
  • Automated Forensic Capture: Automatically capturing system snapshots and memory dumps upon critical threat detection.
